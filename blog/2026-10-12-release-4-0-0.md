# ABCD v4.0.0 Release: Transition to LSP, Modularity, and Interoperability

We are pleased to announce the release of ABCD version 4.0.0. This update represents a historic architectural leap, marking the transition of ABCD from a traditional ILS (Integrated Library System) to a true plugin-based LSP (Library Services Platform). The new version brings a modular approach, a native REST API, and expanded support for different types of collections.

Below, we highlight the main new features and structural improvements in this version:

### 🧩 Plugin-Based Modular Architecture

* **Plugin System:** The system core now operates with a robust plugin architecture, allowing the expansion of services without the need to modify the central code (core).
* **On-Demand Installation:** Legacy or specific databases and modules (such as ODDS, SIP2, Projects, and Experts) have been removed from the default installation. These components can now be managed and installed remotely, ensuring a lighter system adaptable to the needs of each institution.

### 🔗 Interoperability and Data Export

* **Native REST API:** Implementation of a complete REST API for direct and secure access to databases, featuring centralized API key management, SHA256 encryption, and read/write scope control.
* **Batch JSON Export:** New integrated workflow for exporting databases in JSON format, allowing extraction in the native ISIS format or with direct mapping to the Dublin Core standard.
* **Export Resilience and Management:** The data conversion engine was restructured to process blocks individually, ensuring high tolerance against malformed markup, control characters, and UTF-8 encoding failures. The interface includes a real-time progress bar and a manager for secure downloading and deletion of generated files.

### 🏛️ Museum Management (SPECTRUM Standard)

* **New Data Model:** Initial implementation of an example database and management module tailored for museums, strictly structured based on the international SPECTRUM standard.
* **Museum OPAC:** New public interfaces and display formats (PFTs) adapted for museum collections, featuring support for attachment metadata, inscription control, and multilingual support.

### 🔍 Public Interface (OPAC) and Search

* **Expert Search:** Introduction of a new direct boolean search interface in the OPAC, accompanied by results organized in collapsible panels to optimize the user experience.
* **Relevance Control and Performance:** Addition of configurable controls for relevance ranking, increased search buffer, and refactoring of the integrated search logic, ensuring more speed and stability for large collections.
* **Metrics and Usability:** Significant performance improvements in search log analysis (OPAC Analytics) and corrections in encoding handling for form submissions with accents.

### 🛠️ Cataloging and System Administration

* **Language Management (LanguageManager):** Implementation of a cascading translation system. Core files are now kept separate from institutions' local customizations (saved in the `content` folder), preventing data loss during updates.
* **Enhanced Data Entry:** Support for a new `HASH` field type (generating cryptographic values for unique identifiers), improved handling of multi-select fields, and integration of a secure assistant for auto-increment (AI) numbering.
* **Security and Interface (UI):** Complete redesign of the central topbar, addition of a native and secure interface for changing passwords (with CSRF protection), and rigorous sanitization of variables to prevent XSS vulnerabilities.
* **Maintenance and Synchronization:** New automated routine for smart synchronization of the copies database with the loans database (loanobjects), and refactoring of the CrunchMF conversion utility for greater reliability on Linux systems.
